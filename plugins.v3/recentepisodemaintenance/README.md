# 最近媒体维护

当前版本 `v1.0.4`，适用于 MoviePilot V3（`>=3.0.0`）。

## 插件说明

定时维护 MoviePilot 最近整理入库的 Jellyfin 电影和剧集。筛选依据是 MoviePilot 整理历史中的整理时间，不使用媒体的实际发布日期。插件根据整理记录的媒体类型自动区分电影和电视剧，不需要单独配置处理类型。

### 1. 刷新最近整理媒体元数据

查询 MoviePilot 最近 N 天内成功整理的电影和剧集记录，电影对应 Jellyfin `Movie`，电视剧单集对应 `Episode`。插件定位对应视频后，比较 Jellyfin 当前标题与 MoviePilot 按当前数据和命名规则生成的整理预览标题；标题不一致时执行刷新，标题一致时跳过，用于处理以下情况：

- 新媒体入库时 TMDb 标题、简介或图片尚未更新；
- 电影或剧集重新入库后，Jellyfin 因网络问题产生了不完整或错误的刮削结果。

刷新模式与 Jellyfin 界面一致：

- 扫描新的和有修改的文件；
- 搜索缺少的元数据；
- 覆盖所有元数据（默认）。

“覆盖所有元数据”会覆盖现有元数据。“替换现有图片”默认开启，可以单独关闭；扫描模式不执行覆盖操作。媒体库启用 NFO 保存后，Jellyfin 会按自身设置更新 NFO 文件。

同时启用元数据刷新和重新整理时，标题不一致的媒体本轮只提交 Jellyfin 刷新，并暂缓重新整理。后续运行再次确认标题一致后，才会执行重新整理；重新整理前还会重新获取一次安全预览。重新整理后若 Jellyfin 又产生错误标题，后续运行会再次检测并刷新。

对于剧集，MoviePilot 整理预览仍使用“第 N 集”“Episode N”等占位标题时，插件不会把任何非占位 Jellyfin 标题直接认定为权威标题。MP 与 Jellyfin 使用同一集的占位标题时视为当前数据一致，不执行无意义的刷新；Jellyfin 当前标题非空且没有明显异常时会暂时保留。仅当 Jellyfin 标题为空、占位集数与 MP 不一致、显示 Unknown/未知/未命名、包含季集编号、等于剧名或完整文件名时，插件最多提交一次元数据刷新。此后无论 Jellyfin 得到正常标题还是异常标题，都不会因同一个 MP 占位标题循环刷新或重新整理。电影不使用剧集占位标题规则。

剧集占位标题记录按 24、48、72 小时低频复查，并在到期时重新生成 MoviePilot 预览。MoviePilot 取得非占位标题后，恢复正常的刷新和重命名判断；到达最近 N 天期限时最后一次预览仍为占位标题，则保留 Jellyfin 当前结果并将记录标记完成。插件无法判断数据源未提供的标题，因而不会凭空生成文件名。

插件会保存每条整理记录的处理状态和最近一次整理预览。刷新成功后等待 30 分钟再确认，避免 Jellyfin 尚未完成处理时重复提交刷新；插件每 10 分钟轻量检查一次附件生成、旧附件清理和刷新确认等短时等待任务是否到期，没有到期任务时不会查询整理历史、生成整理预览或访问 Jellyfin。刷新或重新整理过的记录会在后续运行中优先复查，确认 Jellyfin 标题一致且按当前规则生成的文件路径不再变化后，该记录才处理完成。同一媒体连续提交 3 次元数据刷新后标题仍不一致时，会停止自动刷新并提示人工检查；Jellyfin 连接失败不计入刷新次数。尚未发生过刷新或重新整理的正常记录按 24、48、72 小时逐步降低复查频率，以发现 TMDb 后续补充的正式标题；到期复查和新记录会交替进入检查范围，避免其中一类长期等待。最近 N 天只限制新记录进入队列，已经进入队列的记录即使超过该范围也会保留到实际完成，不会因单轮检查数量不足而丢失；超过范围的正常记录在轮到最终检查并确认无变化后完成。待刷新和待重命名复查记录直接使用已保存的预览，避免无意义地重复请求；剧集占位标题监测记录到期时会重新生成预览。为避免异常命名规则反复修改文件，连续重新整理两次后预览路径仍变化时会停止自动处理，并在日志中提示人工检查。

“单次最大处理数量”限制每轮元数据刷新、重新整理与弹幕补全的合计操作数。标题一致、命名未变化、弹幕已齐全等无需操作的记录不占用该数量；媒体维护与弹幕补全分别最多检查该数量五倍的整理记录。达到操作上限后，尚未执行的记录会保存为待复查并在后续运行继续。

“重新处理需人工检查记录”是一次性开关。保存配置后，插件会按失败阶段重置对应重试次数并立即重新入队，在随即启动的运行中按单次操作上限处理，不再额外等待附件或清理冷却时间：附件生成失败先检查附件并按需重新整理，旧附件清理失败继续执行清理，其他记录重新从刷新或重新整理阶段检查。开关保存后自动关闭。运行总结和通知会列出全部需人工检查记录的媒体名称、文件路径和原因。

配置项：执行周期，最近 N 天，媒体服务器，维护媒体库，刷新模式，是否替换现有图片，重新处理需人工检查记录，单次最大处理数量。

### 2. 重命名最近整理媒体文件

查询同一批 MoviePilot 整理历史记录，并调用 MoviePilot 自身的历史记录重新整理功能。整理方式、目标存储和刮削流程沿用原整理记录，不直接修改文件名。同一媒体同时存在视频和字幕等整理记录时，以视频记录作为判断基准，并记录同批附件历史；普通字幕只有在确认新名称对应文件已经生成后才会清理旧名称文件。

实际执行时使用 MoviePilot V3 的重新整理模式，并核对视频的执行回执。“已整理过”或覆盖跳过不会被计为整理成功；后台处理中或回执不明确时转入人工检查，请先确认 MoviePilot 整理队列中的结果再重试。新视频未生成时，日志会列出原文件和预期新文件路径；新视频存在后才判断同名 NFO、图片是否缺失。

用于文件命名模板包含媒体标题的情况，例如新剧刚发布时文件名仍是“第 3 集”，或电影标题后续被修正，待 TMDb 更新正式标题后重新整理文件名。

“清理旧名称附件”默认开启。插件会在重新整理前记录与旧视频同名的 NFO、图片、字幕、弹幕和 trickplay 目录；确认新视频、NFO 和图片就绪后延迟清理，再触发 Jellyfin 扫描并复查一次。Jellyfin 扫描提交失败时，相关记录会保留为等待扫描，下一轮先重试扫描，不会提前标记完成。普通字幕只有在新名称对应文件已经存在时才会删除旧文件；XML 弹幕及同名 .danmu.ass 会在调用 MoviePilot 重新整理前改成保护名称，整理成功后再归位到新视频名称，若新名称文件已经生成则删除保护副本。插件不会扫描或删除未被本次重命名记录的其他文件。同一媒体出现新的下载整理记录时，仍在保护附件、等待清理或等待扫描的旧记录会先完成关键步骤，再处理新记录。

配置项：是否启用重新整理，试运行模式，是否跳过命名未变化的文件，是否清理旧名称附件，单次最大处理数量。

### 3. 补全缺失弹幕

此功能默认关闭，当前仅对接 LogVar 弹幕 API，并依赖支持统一 `DanmuID` 元数据标识及单项刷新接口的 [Jellyfin Danmu 插件](https://github.com/cxfksword/jellyfin-plugin-danmu)。电影和电视剧单集都来自同一批 MoviePilot 成功视频整理记录，不额外扫描整个媒体库。

启用前请完成以下配置：

1. 在 Jellyfin Danmu 中启用“弹幕API”来源，填写 LogVar 服务地址，并在需要维护的媒体库中启用 Danmu。
2. 在本插件中填写 MoviePilot 容器可访问的“LogVar 弹幕 API 服务器地址”，例如 `http://服务器IP:9321` 或 `https://域名/Token`。填写基础地址，不要附加 `/api/v2/match` 等接口路径；Token 可放在服务地址的路径中，不支持查询参数形式。本插件不在日志中输出该地址或 Token。
3. 开启“补全缺失弹幕”。是否生成 ASS，以及字体、字号、透明度等转换选项，沿用 Jellyfin Danmu 的配置。

插件先检查视频同名的 XML 和 `.danmu.ass`。缺少 XML 时，剧集使用“剧名 SxxExx”查询，例如 `一念永恒 S01E171`，不附加整部剧的首播年份；电影使用“片名 (年份)”查询，保留同名电影的年份校验。

剧集的别名、跨季、连续集数及 LogVar 中配置的季集映射由 `/api/v2/match` 执行，例如将 `一念永恒 S01E171` 映射为“完结季 (2026) 第 6 集”。本插件不再通过自定义剧名后缀、来源年份、季集相等或分集名称格式重复判断匹配；`遮天 年番1 / 遮天_184`、`我家那闺女2026 / 第6期上` 等格式不会因此被拒绝。映射判断依赖 LogVar，本插件不自行猜测偏移量。

执行前仍要求 LogVar 明确返回匹配成功且目标唯一，区分电影与剧集，并查询来源作品详情核对作品 ID 和分集 ID 的唯一归属。匹配结果与详情可以使用不同的显示名称，日志优先展示详情中的名称；这些检查确保接口数据关系一致，并不证明 LogVar 的内容匹配绝对正确，建议先通过试运行核对映射。电影仍保留片名、年份以及作品只有一个分集的检查。

剧集使用已确认的单集 ID，电影使用作品 ID。匹配不唯一、多集视频、特典、来源作品无法确认或电影作品包含多个分集等情况不会猜测下载，而是在总结中列出文件、查询名称、返回作品和具体拒绝原因。LogVar 未匹配时不会绕过结果随意选择其他剧集；同一来源作品的详情仅在本轮内复用，下一轮重新获取。

匹配通过后，插件读取并保留 Jellyfin 原有元数据，只更新该媒体的 `DanmuID`，由 Danmu 下载 XML 并按配置生成 ASS；正确 ID 已存在时，仅请求该媒体的弹幕刷新，不刷新整季。此操作不调用 MoviePilot 整理预览、不修改 Danmu 的弹幕源排序或全局配置，也不提交 Jellyfin 的元数据覆盖刷新。

写入关联时保留标题、简介、季集编号、其他媒体标识和锁定设置等可编辑信息，不提交播放状态、Trickplay 等展示数据。Jellyfin 明确拒绝提交时会记录脱敏后的具体错误并进入有限次重试，不再当作等待下载；超时或服务端异常时先回读 `DanmuID`，无法确认结果的请求才先等待文件检查，避免立即重复提交。

其他弹幕源可以继续开启。MoviePilot 和 Jellyfin 网络不同的情况下，可填写不同的 LogVar 访问地址：本插件通过 MP 可访问的地址查询匹配，Danmu 通过 Jellyfin 可访问的地址下载。两个入口必须连接同一个 LogVar 服务，并使用相同的媒体 ID 映射；插件不会自动证明不同入口属于同一服务，也不会修改 Danmu 的地址。若 Danmu 配置了“允许的平台”，匹配结果必须符合该限制；配置了“允许的采集源”但无法验证来源时会停止自动补全并提示检查。

文件处理规则：

- XML 已有效，且 ASS 已存在或 Danmu 未启用 ASS：跳过；
- 已有 XML 但缺少 ASS，或 XML 无效：保留原文件并提示人工检查，不重新下载覆盖；此功能不是已有 XML 的单独转 ASS 工具；
- 已有 ASS 但缺少 XML，且 Danmu 开启 ASS 转换：为避免覆盖现有字幕，不自动下载；
- 正在刷新、重新整理、等待附件、扫描或清理的媒体：先完成原有流程，再补全弹幕。

弹幕检查以实际视频文件为准，不把尚未执行的重新整理预览路径当作当前文件。视频已重新整理且旧路径消失时，才使用已提交整理结果中实际存在的新文件。

新加入 Jellyfin 不满 30 分钟的媒体会先给 Danmu 自动下载留出时间。请求提交后约 10 分钟检查文件，确认阶段只检查文件，不调用 MoviePilot 或下载接口；等待 ASS 最多再检查两次。未生成 XML 的任务约 60 分钟后重试，匹配或提交最多尝试 3 次，之后提示人工检查；可通过“重新处理需人工检查记录”重新入队。延迟检查以每 10 分钟的服务调度为准，不会每 10 分钟重复下载。

“匹配到剧集”不等于该来源有弹幕。未生成 XML 的任务在重试下载前，会先向 LogVar 复核当前来源的 JSON 弹幕内容；返回 0 条时不再请求 Jellyfin 下载。明确无匹配或空弹幕累计确认三次后停止自动重试，日志列出查询、来源及具体原因；这仅表示当前匹配来源暂不可用，不代表所有平台都没有弹幕。429 限流、超时、权限错误、服务异常和无效响应不会计为零条弹幕。

正式运行采用持久化弹幕队列，普通任务约每 21 秒提交一项，滑动窗口内每分钟最多预留 3 次弹幕内容请求；失败后的 JSON 内容复核和随后的下载共预留两次额度，因此这类任务会更慢。未提交的任务自动留队继续，限流等待不计失败或重试次数，也不会让任务线程长时间休眠。限流状态在重新运行或重启后继续生效；无法保存限流状态时停止提交。队列调度仅在启用弹幕补全且关闭试运行时注册，空队列只读处理状态，有到期任务时按历史 ID 查询对应记录，不进行 MoviePilot 整理预览；整理历史已删除的任务会移出队列。每轮操作上限仍适用于当次维护，留队弹幕由后续独立调度逐项提交。

该限流只控制本插件的提交和内容复核，不能限制 Jellyfin Danmu 自动下载或其他客户端；Jellyfin 内部排队也可能影响实际下载时间，因此不能保证全局无 429。收到限流响应后暂停提交约 60 分钟。已完成的 XML/ASS 每天复核，不在每次短时任务中重复读取。元数据、附件与清理的 10 分钟复查只查询相应到期记录，不夹带新记录、日常监测或全库弹幕检查。

“重新处理需人工检查记录”不会清除上述无数据累计次数，但每次手动重新入队会单独给予两次可用性复核机会；第一次仍无数据时约 60 分钟后再复核一次，两次都无数据才再次停止，不受历史累计次数提前截断。已有弹幕数据时立即恢复正常下载流程，不必用满两次。普通首次提交不额外读取弹幕内容；每轮内容复核最多执行“单次最大处理数量”次，不调用 MoviePilot 整理预览、不落盘弹幕，也不自行转换 ASS。确认等待阶段仍只检查文件。

LogVar 连续 3 次连接失败、超时或返回 HTTP 429/5xx 时，本轮停止后续弹幕请求；地址、证书、权限或响应格式异常时立即停止。尚未请求的媒体约 60 分钟后重试，不增加其失败次数。连接失败请检查 MoviePilot 容器到 LogVar 的网络，不能仅以浏览器或 Jellyfin 能访问作为判断依据。

Jellyfin 弹幕提交连续失败 3 次时也会暂停本轮后续请求；明确的参数、权限或接口错误会立即暂停。尚未提交的媒体约 60 分钟后重试，不计入失败次数，已提交但结果不确定的媒体仍按文件确认流程处理。

接口接受请求不等于下载成功。试运行及正式匹配日志会显示“查询剧名季集 → 来源作品 / 来源分集”和分集 ID，便于核对跨季映射。日志与通知在“本轮检查”中列出弹幕检查数量，在“操作统计”中列出弹幕试运行、提交、确认完成及暂不可用数量，在“当前状态”中分别列出弹幕等待处理、需人工检查和无资源已暂停数量，并保留明细。明确暂无匹配或弹幕不计入执行失败；网络、接口、匹配关系和文件异常仍按失败或人工检查处理。最终以同名弹幕文件实际生成并通过内容检查为准。重新整理提交后附件延迟补齐的，会在后续确认就绪时补记一次成功，不重复计算操作次数。

### 4. 试运行模式

试运行模式下只查询 MoviePilot 整理记录、匹配 Jellyfin 条目、生成重新整理预览或查询 LogVar 匹配结果，不刷新元数据、不写入弹幕关联、不提交弹幕下载，也不修改文件。

标题不一致的媒体在试运行中同样会暂缓重新整理，用于预览正式运行时“先刷新、后续再整理”的处理顺序。

首次使用建议开启试运行模式，并将单次最大处理数量设置为 1。

## 安全说明

- 新任务只来自最近 N 天内成功的 MoviePilot 电影和剧集整理记录，已入队任务会保留到完成；
- 插件以 MoviePilot 整理记录的媒体类型区分电影和电视剧，分别匹配 Jellyfin `Movie` 和 `Episode`；未知类型会安全跳过；
- Jellyfin 按媒体路径和唯一文件名匹配，剧集无法直接匹配时再按剧集目录降级查找；
- Jellyfin 当前标题与 MoviePilot 当前整理预览中的媒体标题一致时，跳过元数据刷新；
- 不直接重命名主视频文件，由 MoviePilot 按历史整理记录重新执行整理；
- 旧名称附件只按重新整理前保存的精确路径清理，并在新附件就绪后执行；
- MoviePilot 支持整理预览时，会先预览新路径，文件名没有变化时可自动跳过；
- 待刷新和待重命名复查的记录会优先进入后续运行，尚未操作的正常记录按 24、48、72 小时逐步降低复查频率，操作后确认正常的记录不再重复处理；
- 每次运行开始先检查 MoviePilot 整理历史、整理预览和 Jellyfin 服务是否可用，兼容性检查失败时不会继续逐条处理；
- 刷新、重新整理、附件清理和媒体库扫描会在调用外部接口前保存操作意图，调用后立即保存结果；状态保存失败会有限次重试并停止本轮，下一轮根据遗留意图恢复对应阶段；
- 开启通知后，每次完整运行都会发送 MoviePilot 摘要；每 10 分钟的轻量到期检查在没有到期任务时不会启动完整运行，也不会发送消息；
- 单个媒体处理失败不会中断整次任务；处理状态无法可靠保存时会停止本轮，以避免重复执行外部操作。

## 推荐测试步骤

1. 保持试运行模式，将单次最大处理数量设置为 1，并开启需要测试的功能。
2. 确认日志显示的 MoviePilot 整理记录、Jellyfin 条目和预览文件名正确。
3. 先只测试“刷新最近整理媒体元数据”，确认电影和剧集的 Jellyfin 元数据、NFO 和图片符合预期。
4. 再测试“重命名最近整理媒体文件”，确认主视频和字幕、XML 弹幕、NFO、图片等伴随文件均符合预期。
5. 测试弹幕补全时，先核对试运行中的原媒体与来源作品、分集映射；电影同时核对年份。确认正确后再关闭试运行，检查日志中的提交结果及后续同名 XML、ASS 文件确认结果。
